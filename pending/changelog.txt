🔧 **Claude Code アップデート**
**v2.1.223**
・`strictKnownMarketplaces` と `blockedMarketplaces` のmanaged settingsにオーナーワイルドカードエントリ（`"owner/*"`）を追加し、GitHub orgのすべてのマーケットプレイスリポジトリを一括で許可またはブロックできるようになった
・ワークフローエージェント・forkedスキル・スラッシュコマンド・再開されたバックグラウンドエージェントが要求するサブエージェントモデルが制限されていてparentモデルが代わりに動作する場合に警告を表示するようになった
・クラウドセッションで `claude --teleport <session id>` によりローカルで続きを開始できることを示す `/teleport` ヒントを追加した
・Bashパーミッションバイパスを修正：細工したコマンドがパーミッションチェックから一部を隠せる問題を修正した
・タブや不可視のUnicode文字でパディングされたコマンドが承認ダイアログでコマンドの一部を隠せなくなるよう、パーミッションプロンプトを修正した
・ワークフロースクリプトが動的な `import()` を使ってワークフローサンドボックス外のコードを実行できる問題を修正した
・エージェント定義の `bypassPermissions` モードがorg側のバイパスパーミッション無効ポリシーを無視するパーミッションギャップを修正した
・セッション途中に `/cd` を実行した後でセッションを再開すると空になって戻ってくる問題を修正した
・`vertex_ai/claude-*` や `bedrock/anthropic.claude-*` などのプロバイダープレフィックス付きIDで登録されたClaudeモデルをゲートウェイのモデル探索が隠してしまう問題を修正した
・Anthropicのモデル IDでない `modelOverrides` のキーがセッションの正規モデルIDとして扱われていた問題を修正した（不明なキーはドキュメント通り無視されるようになった）
・managed settingsを修正：サーバー側から配信された設定がマシンローカルの `managed-settings.json` やMDMプロファイルのenvブロックを無効化しなくなった（admin envはキー単位でマージされる）
・sandboxの `sandbox.filesystem.denyWrite` が作業ディレクトリを対象にしている場合にLinux上でサンドボックス化されたコマンドの起動が失敗する問題を修正した
・forkedバックグラウンドエージェントが再開時にforkの親プロンプトの再構築に失敗した際、セッション残りの間ずっと「already resuming」でスタックする問題を修正した
・再開したセッションの履歴に不正な形式のdiagnosticsアタッチメントがある場合、毎ターン失敗またはインタラクティブアプリが無反応のエラー画面になる問題を修正した
・`git push` の特殊な出力をパースする際のまれなハングを修正した
・`CLAUDE_CODE_DISABLE_1M_CONTEXT` の対象を固定リストではなくネイティブ1Mウィンドウを持つすべてのClaudeモデルに変更し、auto-compactionで200Kに制限するようにした（auto-compactionがセッションを200K以下に保てていない場合に起動時警告が表示されるようになった）
・auto-compactを変更：未知のモデルIDのセッションを、コンテキストウィンドウを超えて拡大させる代わりに、想定コンテキストウィンドウ内に留めるようになった（以前の動作に戻すには `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1` を設定する）
・`/review` を `/code-review` のエイリアスに変更（`/code-review <level> <pr#>` で現在のdiffやPRをレビューできる。深いクラウドレビューには `/code-review ultra` を使う）
・`/code-review` をレベル指定なしで実行すると前回入力したレベルを再利用するように変更（変更するには `/code-review high` のようにレベルを指定する）
