🔧 **Claude Code アップデート**
**v2.1.165**
・バグ修正と信頼性の向上

**v2.1.163**
・`requiredMinimumVersion` と `requiredMaximumVersion` マネージド設定を追加 — Claude Code がバージョン範囲外の場合は起動を拒否し、ユーザーに承認版へのアップグレードを促す
・`/plugin list` コマンドを追加：インストール済みプラグインをリスト表示、`--enabled`/`--disabled` フィルタに対応
・`/btw` に "c to copy" ショートカットを追加：フォーマットを保持したままマークダウン回答をクリップボードにコピー
・Hooks: Stop と SubagentStop hooks が `hookSpecificOutput.additionalContext` を返せるように改善。Claude にフィードバックを提供してターンを継続できる（フック エラーとしてラベル付けされない）
・Skills: コマンド本文に数字の前にリテラル `$` を含めるための `\$` エスケープ構文を追加
・stdio MCP servers が `--resume` 時に hooks/Bash と同じ `CLAUDE_CODE_SESSION_ID` を受け取るように改善
・`claude -p` が最終結果後、バックグラウンドコマンドが終了しない場合でもハングしないように修正 — バックグラウンドシェルは stdin クローズ後 ~5 秒で停止
・Bedrock/Vertex/Foundry で `CI=true` かつ Anthropic API キーが設定されていない場合の `claude -p` の "ANTHROPIC_API_KEY required" エラーを修正
・Bazel と EDR 保護 Go ワークフロー下での bash コマンド失敗を修正：`$TMPDIR` がサンドボックス化されたコマンドのみでなく全コマンドに対して `/tmp/claude-{uid}` でオーバーライドされていた（2.1.154 からのリグレッション）
・Windows で session-env ディレクトリに読み取り専用属性がある場合や OneDrive 内にある場合に Bash コマンドが "EEXIST: file already exists" で失敗する問題を修正
・初期設定ディレクトリで起動時にマネージド設定フェッチが完了した場合、セッション全体でホーム保護パーミッションルールが適用されていなかった問題を修正
・`claude agents` でバックグラウンドセッションを再アタッチ後、Claude Code 更新時に実行中のバックグラウンドタスクが失われていた問題を修正
・Esc キーでエージェントビューを終了する際のターミナルズレと複数秒のハングを修正
・デスクトップアプリでバックグラウンドタスクチップの Stop をクリックしても、基となるプロセスがすでに終了している場合にチップがクリアされなかった問題を修正
・ペースト操作の終了マーカーがターミナルでドロップされた後、キーボード入力が永続的に反応しなくなる問題を修正
・Hook の `if: "Bash(...)"` 条件が `$()` または `$VAR` を含むすべての Bash コマンドで発火していた問題を修正；パターンはサブシェルとバックティック内のコマンドにも一致するようになった
・ホームディレクトリパス上の deny ルール（例：`Read(~/Desktop/**)` ）が `$HOME` 経由でパスを参照する Bash コマンドをブロックしていなかった問題を修正
・パネルダイアログ（/mcp、/plugins など）を閉じた後、トランスクリプトに迷子の "(no content)" 行が残っていた問題を修正
・バックグラウンドエージェントセッションが Claude Code バージョン更新時にバックグラウンドで更新されるように改善。更新後のセッション起動がコールドリスタート待機なしに実行されるようになった
・組み込みコマンドとスキルの `/` メニューの説明をより明確に
・サブスクリプション切り替え提案がトーストではなくスタートアップ告知スロットに表示されるように変更
・`claude agents` をステートグループビューからディスパッチする際、セッションがエージェントビューが開かれたディレクトリで開始されるようになった
